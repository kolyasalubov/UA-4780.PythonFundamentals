# Archery Club Flask Application

Flask-застосунок для клубу олімпійської стрільби з лука. Проєкт поєднує публічний сайт для запису новачків на тренування, блог із тематичними постами та легку адмінку для керування контентом і заявками.

## Що вміє застосунок

- показує головну сторінку клубу з акцентом на запис новачків;
- відображає розклад тренувань і блог про олімпійську стрільбу з лука;
- приймає заявки з форми запису та зберігає їх у SQLite;
- надає легку адмінку без авторизації для керування постами, розкладом і статусами заявок;
- автоматично створює таблиці та може додавати стартові seed-дані під час запуску.

## Технології

- Python
- Flask
- Flask-SQLAlchemy
- SQLite
- Pytest

## Важливе зауваження

Адмінка в цій версії не має логіну й пароля. Це зручно для навчального або локального використання, але не підходить для продакшн-доступу без додаткового захисту на рівні авторизації, мережі або reverse proxy.

## Залежності та версії

`requirements.txt` використовує сумісні діапазони версій, а не повністю відкриті залежності:

```text
Flask>=3.1,<3.2
Flask-SQLAlchemy>=3.1,<3.2
pytest>=9.0,<9.1
```

Такий підхід дає два практичні плюси:

- проєкт не зависає на одній точній версії без потреби;
- випадкові несумісні оновлення між мажорними або мінорними гілками не потрапляють у середовище непомітно.

## Рекомендована версія Python

Проєкт орієнтований на сучасний Python 3. Якщо у вашому середовищі виникнуть проблеми з інсталяцією або запуском на Python 3.14, рекомендовано локально перейти на Python 3.13, а не ускладнювати проєкт додатковими обхідними рішеннями.

## Швидкий старт

### 1. Створення та активація віртуального середовища

Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Windows CMD:

```bat
python -m venv venv
venv\Scripts\activate.bat
```

Linux або macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Встановлення залежностей

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Необов'язкове налаштування через environment variables

За замовчуванням застосунок запускається через `DemoConfig` (з демонстраційними значеннями). Якщо потрібно, поведінку можна перевизначити через змінні середовища.

Windows PowerShell:

```powershell
$env:SECRET_KEY = "change-me-for-real-usage"
$env:FLASK_DEBUG = "1"
$env:AUTO_SEED_ON_STARTUP = "1"
```

Linux або macOS:

```bash
export SECRET_KEY="change-me-for-real-usage"
export FLASK_DEBUG=1
export AUTO_SEED_ON_STARTUP=1
```

Підтримувані змінні:

- `SECRET_KEY` — секретний ключ Flask; у `DemoConfig` має локальний fallback, а в `ProdConfig` його варто задавати явно;
- `FLASK_DEBUG` — керує debug-режимом у `DemoConfig`;
- `AUTO_SEED_ON_STARTUP` — вмикає або вимикає автоматичне наповнення стартовими даними під час запуску demo-конфігурації.

### 4. Запуск застосунку

```powershell
python run.py
```

Цей сценарій запускає застосунок з `DemoConfig` за замовчуванням.

Якщо потрібно явно створити застосунок із production-конфігом, фабрика підтримує це окремим параметром:

```python
from app import create_app

app = create_app(config_object="app.config.ProdConfig")
```

Після запуску відкрийте:

- публічний сайт: `http://127.0.0.1:5000/`
- адмінку: `http://127.0.0.1:5000/admin`

## Як працює перший запуск

- Flask автоматично створює таблиці в SQLite;
- якщо `AUTO_SEED_ON_STARTUP` увімкнений, застосунок додає стартові пости та тренувальні слоти, коли база порожня;
- якщо база вже містить дані, seed не дублюється;
- у тестах автосід вимикається, щоб fixtures і перевірки залишались детермінованими.

## Де зберігаються дані

Основна SQLite-база для локального запуску зберігається всередині проєкту:

- `instance/archery_club.db`

Папка `instance/` уже внесена в `.gitignore`, тому база не потрапляє в git, але водночас не виходить за межі папки проєкту. Це спрощує і локальну навігацію, і повне видалення проєкту.

## Основні сторінки

- `/` — головна сторінка клубу;
- `/trainings` — сторінка з розкладом і форматами занять;
- `/blog` — список постів;
- `/blog/<slug>` — окрема сторінка поста;
- `/contacts` — контакти;
- `/admin` — головна сторінка адмінки;
- `/admin/posts` — керування постами;
- `/admin/schedule` — керування розкладом;
- `/admin/leads` — перегляд і оновлення статусів заявок.

## Як користуватись сайтом

1. Відкрийте головну сторінку.
2. Ознайомтесь із клубом, тренуваннями та постами блогу.
3. Заповніть форму запису новачка.
4. Після відправлення заявки вона з'явиться в адмінці в розділі `Leads`.

## Як адмініструвати застосунок

### Пости

1. Перейдіть у `/admin/posts`.
2. Створюйте нові пости, редагуйте наявні або видаляйте непотрібні.
3. Поле `slug` має бути унікальним, бо використовується в URL поста.
4. Опція `featured` виводить пост у вибраних матеріалах на головній сторінці.

### Розклад

1. Перейдіть у `/admin/schedule`.
2. Додавайте або редагуйте тренувальні слоти.
3. Поле `capacity` має бути додатним цілим числом.
4. Поле `featured` показує заняття на головній сторінці.

### Заявки

1. Перейдіть у `/admin/leads`.
2. Переглядайте нові заявки з форми запису.
3. Оновлюйте статуси `new`, `contacted` або `booked`.

## Який файл за що відповідає

- `run.py` — точка входу для локального запуску, debug-режим береться з конфігурації;
- `app/__init__.py` — фабрика Flask-застосунку, реєстрація blueprint-ів, `db.create_all()`, умовний автосід і CLI-команда `seed`;
- `app/config.py` — конфігурація застосунку, env-перемикачі та шлях до SQLite-бази в `instance/`;
- `app/extensions.py` — ініціалізація SQLAlchemy;
- `app/models.py` — моделі `Post`, `TrainingSlot`, `Lead`;
- `app/seed.py` — стартові дані для постів і розкладу;
- `app/public/routes.py` — маршрути публічної частини і ручна валідація форми запису;
- `app/admin/routes.py` — маршрути адмінки, CRUD і ручна валідація адмінських форм;
- `requirements.txt` — список залежностей із сумісними діапазонами версій;
- `tests/` — автоматичні перевірки, включно з edge-case сценаріями для валідації.

## Як запускати тести

```powershell
python -m pytest tests -v
```

Що перевіряють тести:

- створення застосунку й конфігурації;
- seed-дані;
- публічні сторінки й блог;
- створення заявок;
- базові CRUD-операції в адмінці;
- edge cases на кшталт невалідного email, дубльованого `slug`, некоректного `capacity` та невалідного статусу заявки.

## Як відтворити чисте середовище

Якщо хочете перевірити проєкт із нуля:

1. Видаліть `venv` або `.venv`, якщо середовище вже існує.
2. Створіть нове віртуальне середовище.
3. Встановіть залежності з `requirements.txt`.
4. За потреби видаліть `instance/archery_club.db`, щоб пересоздати локальну базу.
5. Запустіть `python -m pytest tests -v`.
6. Запустіть `python run.py` і перевірте сайт вручну.

## Що можна видаляти без шкоди для проєкту

Поки застосунок зупинений, безпечно видаляти:

- `venv/` або `.venv/` — віртуальне середовище;
- `.pytest_cache/`, `.pytest_tmp/`, `.pytest_tmp_local/`, `pytest_tmp_local/` — артефакти тестів;
- `pytest-cache-files-*` — тимчасові файли pytest;
- `.tmp/`, `.tmp-server-*.log` — тимчасові файли локальних перевірок;
- `__pycache__/` і `*.pyc` — кеш Python;
- `instance/archery_club.db` — якщо хочете повністю скинути локальні дані й заново створити базу;
- `instance/*.db-journal` — супровідні файли SQLite, якщо вони з'явилися після запису.
